# Bookora Phase 16 — Customer Receipt & Focus Refetch Hotfix Handoff

## Status

`DONE` cho source implementation và automated verification của hotfix.
Manual browser/runtime là `NOT RUN` theo yêu cầu trực tiếp của người dùng.
Không có WebSocket, SSE, polling, auto-complete, RETURNED hay refund workflow.

## Business flow

- Admin chuyển `PACKING → SHIPPING` như Phase 16 hiện có.
- Customer dùng command riêng
  `POST /customer/orders/:orderId/confirm-received`.
- Command chỉ ghi `customerConfirmedReceivedAt` và event
  `CUSTOMER_RECEIPT_CONFIRMED`; Order vẫn `SHIPPING`.
- Admin chỉ được chuyển `SHIPPING → COMPLETED` sau khi receipt đã được xác
  nhận. Backend trả `ORDER_CUSTOMER_RECEIPT_REQUIRED` nếu gọi trực tiếp quá
  sớm.
- `SHIPPING` vẫn không thể hủy. Receipt confirmation không đổi Payment, tồn
  kho hay InventoryMovement.

## Data model and concurrency

- Reused `OrderStatusHistory`; không tạo bảng history thứ hai và không tạo
  self-transition `SHIPPING → SHIPPING`.
- Added `Order.customerConfirmedReceivedAt`.
- Added `OrderHistoryEventType` và `OrderStatusHistory.eventType`; `toStatus`
  nullable cho event không phải transition.
- Receipt uses conditional `updateMany` claim inside a transaction. Duplicate
  và lost concurrent claim return current state without a second timestamp or
  event.
- Migration:
  `prisma/migrations/20260727223000_phase16_customer_receipt_confirmation/migration.sql`.
- Migration deploy/status/diff: applied, database up to date, no difference.

## API and projections

- Customer list/detail return `customerReceiptConfirmation` and
  backend-authoritative `allowedActions.confirmReceived`.
- Admin detail returns receipt projection, typed history event and
  `completionReadiness`.
- OpenAPI exported and validated: 175 operations, 202 schemas.
- Frontend OpenAPI artifact, Orval client and generated Zod were regenerated by
  `npm run gen:api:local`; generated files were not edited manually.

## Frontend behavior

- Customer detail shows `Đã nhận hàng`, shadcn-vue AlertDialog, pending guard,
  Vietnamese success/error toast and confirmed timestamp (`HH:mm dd-MM-yyyy`,
  Asia/Ho_Chi_Minh).
- Customer success invalidates detail/list and publishes the existing order
  cross-tab event; it does not invalidate Inventory.
- Admin detail shows a visible disabled `Hoàn thành đơn` button with tooltip
  while waiting, enables it after receipt, and renders the Customer receipt
  event in the vertical timeline.
- Existing order-sync listener invalidates Customer caches and Admin
  list/detail caches for the selected branch in another tab of the same browser
  context.

## Focus refetch policy

- Customer/Admin order detail: `staleTime: 20_000`.
- Customer/Admin order list: `staleTime: 45_000`.
- Inventory stock/movement/receipt lists: `staleTime: 45_000`.
- All above enable `refetchOnWindowFocus` and `refetchOnReconnect`.
- No `refetchInterval`, timer or global static-catalog policy change.
